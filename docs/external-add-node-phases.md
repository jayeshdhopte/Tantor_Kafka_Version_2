# External Add Node: agreed phases and acceptance

Each phase requires a demonstration and acceptance checks before moving forward. Demonstration with fixtures is explicitly labelled; it does not count as live cluster acceptance. No phase is considered accepted merely because its code builds.

| Phase | Scope | Acceptance gate |
| --- | --- | --- |
| 1. Integrate the design | React wizard, real external-cluster/enrolled-host APIs, Broker only, deployment disabled | Open Add Node, select a real enrolled host and navigate all screens; no deployment |
| 2. Real readiness | Backend/external-agent connectivity, capability, package/checksum, Java, ports, storage, resources, cluster-health and operation checks; evidence expiry/context binding | Actual results displayed; failed/missing/stale checks block deployment; preview makes no machine/Kafka changes |
| 3. Broker execution | Atomic host/ID reservations, frozen reviewed profile, final checks, package/config/storage preparation and tracked broker startup | Add a broker to the designated external test cluster from the wizard, with progress |
| 4. Broker verification/recovery | Unfenced registration, stable health, verified inventory publication and interruption reconciliation/resume | No duplicate deployment or repeated formatting after connection loss or backend/agent restarts; broker-only release ready |
| 5. Dynamic controller | Observer startup/catch-up, voter admission and exact quorum verification | Success and lost-response/resume tests without restarting existing services |
| 6. Separate processes | Two IDs and isolated configs/services/storage/logs; controller verified before broker | Both verified before healthy inventory publication; recovery retains admitted controller and resumes broker work |
| 7. Release validation | Permissions, concurrency, old agents, unsupported clusters, failures, monitoring/audit/UI and compatible release artifacts | All supported layouts pass agreed scenarios with deployment/recovery documentation |

## Current phase: 1 — implementation ready, live acceptance pending

Route: `/external-clusters/{id}/add-node`, entered through **Cluster → Nodes → Add Node** for an external KRaft cluster. The internal-cluster route and execution workflow remain separate.

The new wizard reads existing APIs only:

- `GET /api/v1/ui/external-clusters`
- `GET /api/v1/ui/external-clusters/agents`
- Existing read-only active-job inventory

It shows the actual cluster ID/version/mode/environment and enrolled external agents. Missing clusters and empty, stale, assigned or invalid host inventories cannot become a deployment selection. Refresh invalidates selection and returns to the first screen. Broker is selected; controller and separate-process choices are disabled. Check results show **Not run**. Broker node ID is **Not allocated**. **Deploy broker** is unconditionally disabled; this phase has no inspection/task/deployment POST, reservation or Kafka mutation.
